# Browser capture and parity

## Root cause of the reported mismatch

The previous PNGs came from a print renderer. Its compatibility layer replaced controls, changed flex/grid behavior and hid mobile table columns. The images therefore did not represent the exact interactive HTML. This workflow is retired.

## Single source of truth

The source files are prototype/index.html, prototype/styles.css and prototype/app.js. The standalone HTML is generated by scripts/build-preview.mjs. START_HERE.html embeds the canonical prototype directly for desktop/mobile review. No independently authored visual mockup is authoritative.

## Local commands

```sh
cd design
npm install
npx playwright install chromium
npm run capture
```

Requirements: a normal Node.js development environment and a supported Chromium runtime. Playwright is a development-only dependency. Commit the locally generated package-lock.json with future tooling changes if this folder becomes part of the repository's development workflow.

## Capture behavior

The script serves design/ on an ephemeral loopback port. It uses one Chromium browser with fresh contexts at 1440×1050 and 390×844 CSS pixels, device scale 1. It opens each route independently and waits for fonts. The reference uses system fonts, so rasterization may vary between operating systems. Browser and source hashes are recorded.

It captures the page as rendered. It does not inject CSS, swap inputs, modify content, hide review controls or remove table columns. It uses full-page PNGs. Loading is captured with the same reduced-motion preference supported by the app. The script checks page-level horizontal overflow and browser errors. The table itself may scroll internally.

Outputs:
- Ten desktop PNGs: six core views plus loading, empty, error and missing graph.
- Six mobile PNGs: core views.
- capture-manifest.json: source SHA-256, browser version, viewport, dimensions and verification status.

If a check fails, the script exits unsuccessfully and the manifest marks the batch failed. Do not call those images accepted baselines. Fix canonical source and capture again.

## Review acceptance

1. Confirm source hashes match the current files.
2. Open the same route at the recorded viewport and 100% zoom.
3. Compare type, spacing, sidebar, controls, graph, table, disclosure and footer.
4. Inspect long pages, mobile wrapping and internal table overflow.
5. Verify interaction checks separately. A screenshot cannot prove behavior.
6. Record accepted captures and remaining defects in docs/07-VALIDATION.md.

Fresh matching PNGs were not generated in this session because browser access was blocked. screenshots/ is a destination, not evidence of a completed capture run. reference-boards/ retains the old images only for history.
